# 手动自动更新发布指南（不使用 GitHub Workflow）

本项目现已支持通过以下仓库进行 Tauri 自动更新：
- https://github.com/Perxenic-Acid/SSMT4

应用会检查如下更新地址：
- https://github.com/Perxenic-Acid/SSMT4/releases/latest/download/latest.json

## 一次性初始化

> **重要：** 本仓库开源发布后，更新签名私钥**绝不能**再提交到仓库中。旧密钥对（曾存在于本项目及 git 历史中）已视为泄露并废弃，必须重新生成。

1. 在**项目目录之外**生成新的 updater 密钥对（例如 `%USERPROFILE%\.ssmt\`）：

```powershell
bunx tauri signer generate -w "$env:USERPROFILE\.ssmt\updater-signing.key"
```

- 生成时会要求设置私钥密码，请使用一个**强密码**并妥善保管（建议存到密码管理器）
- 命令输出的公钥字符串需要复制保存

2. 将生成的公钥字符串替换到：
- src-tauri/tauri.conf.json -> plugins.updater.pubkey

3. 私钥文件保存在项目外（如 `%USERPROFILE%\.ssmt\updater-signing.key`），不要提交到仓库。

## 每次发版步骤（手动）

1. 先提升应用版本号：
- src-tauri/tauri.conf.json -> version

2. 在当前终端导出签名密钥环境变量（以项目外私钥为例）：

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY_PATH = "$env:USERPROFILE\.ssmt\updater-signing.key"
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = "你的私钥密码"
```

> 也可以直接用 `TAURI_SIGNING_PRIVATE_KEY` 环境变量传入私钥内容（例如 CI 中使用 GitHub Actions Secrets 时）。

3. 构建安装包（scripts/tauri-with-signing.mjs 会读取上述环境变量完成签名）：

```powershell
bun run tauri build
```

> 注意：`bun run tauri` 走的是 `scripts/tauri-with-signing.mjs` 签名包装脚本。如果私钥或密码缺失，脚本会报错并终止，不会静默产出未签名产物。

4.调用ps1脚本生成latest.json



5. 从以下目录收集产物：
- src-tauri/target/release/bundle/nsis/

当 createUpdaterArtifacts 设置为 v1Compatible 时，构建会同时生成 updater 元数据和签名产物。

5. 在 Perxenic-Acid/SSMT4 创建一个新的 Release，然后上传：
- NSIS 安装包
- 签名文件（一个或多个）
- latest.json

6. 确保 latest.json 作为最新版本 Release 的资产被上传。

因为应用使用的是：
- /releases/latest/download/latest.json

所以它始终会从“最新 Release”读取更新元数据。

## latest.json 模板（如需手动编辑）

```json
{
  "version": "4.0.48",
  "notes": "在此填写更新说明",
  "pub_date": "2026-03-20T12:00:00Z",
  "platforms": {
    "windows-x86_64": {
      "signature": "<由生成的 .sig 文件填入签名>",
      "url": "https://github.com/Perxenic-Acid/SSMT4/releases/download/v4.0.48/ssmt4_4.0.48_x64-setup.exe"
    }
  }
}
```

## 运行时行为

在设置页面：
- 点击“Check App Updates（检查应用更新）”
- 若发现新版本，确认更新
- 应用会下载并安装更新包
- 安装完成后重启应用

## 注意事项

- 为了最简访问，发布仓库建议为公开仓库。
- 版本号必须保持单调递增。
- 若检查更新失败，请排查：
  - tauri.conf.json 中的 pubkey 是否正确（必须与签名所用私钥**同一对**）
  - latest.json 地址是否可访问
  - 签名是否与上传的安装包匹配
- 开源后密钥安全要点：
  - 私钥 + 密码只由发布者持有，通过环境变量注入构建流程，永不写入仓库
  - 客户端内置的公钥是公开的，开源不会削弱签名安全性
  - 若私钥曾出现在 git 历史中（本仓库旧版本即如此），请立即重新生成密钥对并更换 tauri.conf.json 中的 pubkey，否则任何人可用旧私钥伪造更新包
  - 如果远程仓库历史中仍包含旧私钥/密码，建议清空重推历史或删除重建仓库（GitHub 会自动扫描公开仓库中的密钥并通知持有者）
