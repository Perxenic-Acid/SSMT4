# 插件市场界面与验证

入口为 `src/views/PluginMarketplace/PluginMarketplace.vue`，使用共享主题变量。
跟随应用当前游戏，左侧搜索并按发现、已安装、可更新筛选，右侧显示选中插件。
刷新和从磁盘安装位于搜索框右侧；本体插件使用自己的作用域提示，不要求选择游戏。

详情分为功能设置、依赖项、权限和插件信息。来源、ID、版本及支持的游戏放在插件信息中，
让设置区使用完整宽度。列表保留来源和状态，短来源标签仅用于展示；官方包验证和
第三方包安装确认仍由原有流程负责，不能根据名称、作者或标签推断可信来源。

DLSS5 设置位于已安装且对当前游戏启用的插件详情内，由
`src/plugin/components/Dlss5GraphicsSettings.vue` 提供。原神先显示组件状态，
再提供显卡选择、自动下载和离线导入；启动要求始终可见，来源和安装位置可展开查看。
组件部署和热注入约束见 [原神热注入说明](gimi-hot-runtime.md)。

逐游戏兼容性由清单 `compatibility.games` 决定，比较实际游戏配置的 `gamePreset`，
不能用用户自定义的游戏名称判断。注册表拒绝不兼容启用，并在生成启动贡献时忽略旧版
错误选择；市场快照显示 `incompatible`，更新可用不能覆盖此状态。禁用旧状态仍须可用。
原神 Poser（包括开发包 ID）已经声明仅支持 GIMI，限制来自清单，不按插件名称硬编码。
纯本体页面继续使用全局作用域，不强制绑定游戏。

## 异步交互

- 刷新指示等待注册表、官方目录、本地包目录全部完成；目录读取失败保留已有列表，
  在可展开的提示中展示错误，继续提供本地文件安装。
- 切换插件回到功能设置；日志弹窗及清空动作始终绑定打开时的插件，避免异步返回后错配。
- 切换游戏或渲染 API 立即失效旧组件状态、路线和进度，再延迟扫描；旧请求不能回写新状态，
  等待新扫描时不能沿用旧路线发起安装。
- 未安装、未启用或未选择游戏时不挂载 DLSS5 设置，不扫描专有资源。
- DLSS5 状态命令在后台线程执行文件与哈希检查；路线、状态及历史独立返回，路线就绪后
  可配置组件。配置开始即失效旧读取，迟到结果不能覆盖玩家的新选择。
- 开发目录 `local_plugin_packages` 仅 Debug 可用，在后台线程检查压缩包，避免解压、杀毒软件扫描或
  压缩包哈希计算占用 WebView 的交互线程。目录发现不会安装、启用或加载插件 DLL。
- 相同游戏、已安装版本和启用状态的快照更新不卸载 DLSS 设置；实际切换或更新才重读。
  市场页在所有背景模式下关闭页面内部的背景模糊，面板使用较高不透明度的主题底色；
  这也适用于无游戏、空列表和断网状态，不再仅对视频背景启用兼容处理。

### Windows 10 无游戏时整窗闪烁

2026-10-19 的反馈来自刚编译的 Release：没有安装游戏，进入市场后整个窗口持续闪烁。
此前的合成兼容样式仅由 `BGType.Video` 启用，静态背景和无游戏状态仍有两个
`blur(16px)` 面板；没有游戏并不代表页面没有模糊层。市场自身没有定时刷新循环，
生产模式夹具中初次三项目录读取完成后，空闲期间没有重复 IPC、DOM 更新或运行中的动画。

市场及其内部设置现统一关闭 `backdrop-filter`，保留主题色、边框和阴影。
另将加载占位条的 `background-position` 动画改为透明度变化，避免目录响应慢时持续重绘；
渲染性能门禁同步检查无限循环动画中的 `background-position`。

使用真实组件、共享样式和应用内容区布局的生产模式夹具，覆盖无游戏、仅有游戏配置而
无客户端、本体插件、空目录、离线、慢目录、静态及视频模式、中英文、最小窗口、窄窗口和
125% 界面缩放。CPU 模式 Chromium 的一次 1.8 秒加载采样中，修改前有 300 个 Paint
事件，修改后为 0；刷新、搜索和插件切换正常，未扫描未安装插件的资源。
这些结果用于验证合成路径与加载重绘的改动，不能证明目标 Windows 10 的整窗闪烁已消失。

实机验收仍需在原电脑使用本次修改后重新编译的应用：无游戏配置进入市场，目录加载前后
分别停留，搜索、切换插件和刷新，再离线重复。应确认整个窗口稳定、操作可用、左右容器
底部不越界；不以禁用全局 GPU 加速或要求安装游戏作为解决方式。

## 分发与首次安装

### 版本发现与旧 Poser 不显示更新

官方目录来自 `SSMT-Native` 的 GitHub `/releases/latest`，并验证同一 Release 的目录、
资产大小及 SHA-256。市场按插件清单的语义版本显示“可更新”和更新按钮；Native Release
标签、DLL 修改日期、主应用版本都不能替代插件版本。刷新不会自动下载、安装或启用插件。

2026-10-19 核查发现，本机 Poser DLL 仍为 10 月 8 日安装的 1,291,776 字节版本，
GitHub v0.1.7 中的 DLL 已为 2,891,776 字节，两者清单及 ABI 查询却都为 `0.1.0`。
因此更新提示未出现；安装器也拒绝覆盖已存在的同版目录。正式应用资源没有携带 Poser，
重新打包 SSMT 不会更新全局 Plugins 中的独立安装包。

修复位于 Native：新增 Poser `0.1.1`，DLL 查询从清单读取版本，停止重打历史 `0.1.0`，
并在正式发布前对照 GitHub 最新已发布标签检查源码变化与包版本。必须先发布包含
`ssmt.poser.genshin-probe-0.1.1.ssmtpkg` 的新 Native Release；仅提交代码或生成 Actions
Artifact 不会改变线上目录。发布后玩家刷新插件市场、显式更新并重启游戏，无需覆盖旧目录。
回归覆盖 GitHub 目录发现新版、更新后选择新版并清除提示、停用状态及目录更旧时不提示降级。

正式版只通过 Native Release 目录按需安装官方插件；不携带插件包、占位清单或
Player Tweaks DLL，也不再伪造 Player Tweaks 的内置安装记录。旧版留下的启用标记
不能启用未安装插件；实际独立安装的包继续保留。第三方文件安装与来源确认不变。

`build_native.ps1` 将开发包写入主仓库 `build/plugin-packages`，仅 Debug 应用可发现。
正式版即使磁盘上残留 `resources/PluginPackages` 也不读取。新装机器在官方目录为空
时显示空列表；官方目录离线时仍保留已安装项目，提示目录读取失败，不能回退成开发包。
Native Release 需要同时提供目录和相应包资产；`publish: false` 的实验版本不会自动发布。

旧版只显示 Player Tweaks 是内置快照先返回的现象，不代表真正安装了包，也不能证明
其他插件 DLL 加载失败。排查时分别检查注册表、官方目录和 Debug 开发目录的结果。
官方目录离线、空目录或无效开发包都不应退出应用。

`plugin_marketplace_startup` 使用 Tauri 实际的资源枚举器检查安装器资源清单，确保旧开发
包和 DLL 即使仍在磁盘上也不会被带入。注册表回归覆盖孤立启用标记、首次安装默认
停用及已有包升级保留选择。开发包验收还须实际打包并安装，不能只检查清单源码。

## Native Release 对接

客户端读取 Native 仓库最新公开 Release 的 `ssmt-plugin-catalog.json`，插件包与目录资产
必须属于同一标签，名称、下载 URL、大小及 GitHub 返回的 SHA-256 摘要必须一致。
目录先按原始字节验证，再解析内容；包下载后继续执行完整哈希、清单与安装路径检查。
有多个版本时市场按插件 ID 展示最新版；安装需要显式点击，首次安装默认停用，
外部 DLSS5 / ReShade 组件仍由相应插件自己的按需获取流程负责。

[v0.1.6](https://github.com/Perxenic-Acid/SSMT-Native/releases/tag/v0.1.6) 有 7 个版本；
当前市场展示 DLSS5 0.2.2、HoYoShade Bridge 0.1.1、Player Tweaks 0.1.0、Poser 0.1.0。
该版打包器把 Poser 未声明的外部依赖写成 `[null]`，曾导致整个官方目录解析失败。
客户端只在官方目录中将这一空依赖表示兼容为 `[]`，损坏的实际依赖对象仍拒绝，
包内清单和第三方目录的校验不变。Native 打包器已修正缺省可选数组的输出。

已用实际 v0.1.6 云端资产完成全部 7 个包的下载、哈希、临时目录安装及注册表重读。
正式发布后可复用以下集成验证；默认测试不联网，显式执行时使用独立临时注册表，
不读取用户配置、不启用插件，也不加载 DLL 或创建图形设备：

```powershell
$env:SSMT_NATIVE_RELEASE_TEST_TAG = 'v0.1.6'
try {
    cargo test --manifest-path src-tauri/Cargo.toml --lib plugin::official_release::tests::published_release_downloads_and_installs_every_package_without_enabling_plugins -- --ignored --exact --nocapture
} finally {
    Remove-Item Env:SSMT_NATIVE_RELEASE_TEST_TAG
}
```

该验证覆盖每个发布版本，包含先安装新版再安装旧版、安装结果对应请求版本、
来源标记持久化及所有游戏预设在未启用时没有运行时贡献。它不代替各游戏实机验收。

## 跨电脑启动验证

跨电脑发布禁止使用 `target-cpu=native`。这会把构建机的 SHA、AVX 等可选指令当作最低
要求；`sha2` 的 `cpufeatures` 在相关特性全部编译启用时会省去运行时检测，第一次检查
插件包哈希就可能在其他 CPU 上触发非法指令。当前 Cargo 配置固定 `x86-64`，
`src-tauri/build_support/windows_cpu.rs` 在 Release 编译时检查实际生效的目标特性，
包括通过环境变量覆盖配置的情况。默认基线保留 Rust Windows x64 所需的 SSE3 /
CMPXCHG16B，静态 CRT 链接不属于额外指令集。

验证命令：

```powershell
cargo test --manifest-path src-tauri/Cargo.toml --test plugin_marketplace_startup
```

压缩包回归使用数据夹具，在独立子进程的 1 MiB 栈中执行完整发现与哈希检查，不加载
图形 DLL。编译配置变化会自动失效旧 Cargo 缓存；交付测试必须使用重新编译后的应用，
只更新 Native 插件或沿用旧安装器无效。不要为排查运行主应用发布包脚本。

实机验收：在原先出问题的电脑上打开插件市场，等待目录完成、切换插件并重复刷新；
断网时仍能显示已安装项目，Debug 另可显示开发包。若仍退出，从 Windows 事件查看器的
“Windows 日志 → 应用程序”记录应用版本、故障模块和异常代码。`0xc000001d` 表示
非法指令，与 CPU 基线问题吻合；其他异常必须继续按对应模块调查，不能一律归因 CPU。

事件 1005 的空文件名和错误值 `00000000` 不能代替异常代码，也不能据此判定磁盘或
CPU 故障。采集结果为空时先检查查询是否成功；Windows PowerShell 5.1 的日期过滤
可能受自定义区域格式影响，应使用明确的 UTC XPath 查询。

## 滚动边界

页面使用应用内容区的实际高度；左右两列独立滚动，根页面不滚动。左侧内容少时保持
自然高度，超过可用空间时才钳制高度。右侧高度包含内边距与边框，底边与网格行对齐；
普通详情和空选择状态共用该约束，长内容只在右侧内部滚动。

## 验证入口

执行 `node --test scripts/tests/test-plugin-graphics-settings.mjs` 检查作用域隔离、
异步状态、下载与日志绑定，再执行 `bun run build` 完成类型检查和前端构建。
这不是发布包构建，不执行根目录 `build_release.ps1`。

浏览器检查应挂载真实 Vue 组件及共享样式，以临时 IPC 夹具代替 Tauri 后端，
不得为了截图访问真实用户配置或触发下载。一次性预览与截图放在忽略目录，不提交。
夹具不应添加应用没有的全局 `box-sizing` 重置，否则会掩盖百分比高度叠加内边距的问题。
检查左右容器的实际底边是否位于网格与窗口之内，不能仅依赖根容器没有滚动条：
`overflow: hidden` 仍可能裁掉超出的底部。
至少检查 1280×720、应用配置的默认/最小 1080×600、中英文及窄窗口，确认操作不遮挡、无横向溢出，
并检查空列表、目录离线、无游戏、游戏插件禁用、本体插件不依赖游戏和下载进度。
夹具只能证明界面行为，实际下载、原生注入和 NR 渲染需要各自的集成验证。
