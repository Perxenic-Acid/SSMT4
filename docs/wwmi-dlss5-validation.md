# 鸣潮 DLSS5 集成验收

当前状态：软件回归通过后交付实机验收，不代表已验证长期稳定。测试使用 SSMT 直接启动；历史 RHI 专用脚本不是本次入口。

## 准备

1. 更新 SSMT 前端与 Rust 后端。开发环境重新启动 `bun tauri dev`；仅 `build_native.ps1` 不会更新下载、配置与启动逻辑。保留包含 DXGI 共存修复的 SSMT Runtime。
2. 完全退出游戏。若之前由 RHI / Swapper / ReShade 向游戏目录部署过代理，通过原工具恢复；不要手工混装两套 Host。
3. 鸣潮实例选择 WWMI，目标为 `Client-Win64-Shipping.exe`，启用“启动目标程序”。Shell 路径如需使用，应指向同一个游戏 EXE。
4. 在此实例启用 DLSS5，选择匹配显卡的 Profile，自动下载并配置。需要在游戏内开启原生 DLSS；当前尚无已核对的数据库字段用于自动修改，不能将组件安装成功当作输入已满足。
5. 记录 SSMT 版本、Runtime 哈希、显卡/驱动、组件目录和游戏版本。组件目录可从插件设置复制；不要公开完整个人路径或账户信息。

## 按顺序测试

| 项目 | 操作 | 应观察到的结果 |
| --- | --- | --- |
| 基线 | 关闭所有插件，由 SSMT 启动，使用一个已知正常的角色 Mod | 正常 Mod 替换，普通启动不要求插件文件 |
| DLSS5 | 退出游戏后只启用 DLSS5，重新启动 | 本次 INI 使用 DX11；原生 DLSS 打开后出现 NR 成功帧证据，同时 Mod 正常 |
| 画面与操作 | 切换场景、进入/停留角色界面、反复切换模型，切换分辨率 | 无同类卡死/闪退；模型、贴图、输入、ReShade 菜单正常。观察 NR 日志是否继续增长 |
| 重复启动 | 正常退出、重新启动至少三次 | 无遗留进程；不重复首次教程；只有一个 ReShade Host |
| 停用 | 退出后关闭 DLSS5，再启动 | 不注入本次插件 DLL / 环境；玩家保存的启动参数不被永久改写；Mod 正常 |
| 失败继续 | 在隔离测试副本中使组件缺失或校验失败，再启动 | 仅非模态提示，本次跳过 DLSS5，游戏和普通 Mod 继续；恢复副本后可以重试 |
| 组合 | 各个支持鸣潮的插件单独、成对及全部启用 | 单 Host、无资源覆盖、无缺失贡献；不能通过强制关闭某个正常组合算通过 |
| 长时间 | 上述通过后单独安排持续游玩，再退出 | 记录时长、场景及退出行为；短时通过不等同数小时稳定 |

鸣潮启用热路线时，SSMT 只为本次启动加入 `-dx11`，移除冲突 API 开关；其他参数及保存配置保留。关闭插件后沿用原配置。不要用改变保存配置掩盖停用恢复问题。

## 判定与回传

- “DLL 已加载”、Add-on 已加载、只有 ReShade 菜单或普通 DLSS Feature 创建，都不能证明 NR 已运行。记录同次启动的成功 NR / Feature 18 评估证据、时间和游戏画面；日志证据不能代替画质检查。
- 收集组件目录中的 `ReShade.log`、`ReShade.ini`、`ReShadePreset.ini`、`ReShade.ssmt-defaults.json`、`ReShade.ssmt-addons.json`；若有 `.ssmt-pending-files/journal.json`，保留该目录，不手工覆盖恢复记录。
- 同时收集 WWMI 的 `d3d11_log.txt`（若当前版本使用其他日志名则取实际日志）及本次 SSMT 启动日志。确认日志修改时间对应本次测试，分别记录成功和失败的开关组合。
- 若崩溃，保留当次游戏崩溃报告及上述日志。遇到驱动异常停止重复触发，记录时间；本次不扩展为驱动排障。
- 若需要自动控制鸣潮原生 DLSS，请在游戏关闭时提供脱敏设置样本：分别保存 DLSS 关闭和开启后的配置差异，核对真实键名、类型与枚举值后才能实现写入及恢复。

配置准备失败会尝试恢复整组配置与自有 Add-on。若检测到文件随后被修改，则保留实际文件与恢复记录并跳过可选贡献；不会用旧备份覆盖玩家修改。游戏目录中的未知代理仍交给原安装工具恢复。
