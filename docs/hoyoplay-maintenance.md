## 参考基线

本机只读参考 Starward `433dc28a`（MIT）与 FufuLauncher `62adc64`（MIT）。
主要对应 HoYoPlayClient / GamePackageService、Sophon.proto，以及
SophonBuildClient / GameServerConverter / GameChannelSdkService。
两者不作为 SSMT 运行时依赖，SSMT 独立实现 Rust 后台与 Vue 入口。

2026-10-22 读取官方接口确认：旧 `getGamePackages` 给原神返回 5.5.0，但
`getGameBranches` / Sophon Build 返回 7.1.0；崩铁和绝区零的旧压缩包接口也落后。
因此不能以旧 ZIP 包作为当前安装更新基线，更不能用其覆盖已有新客户端。
使用官方当前分支及其可用的预下载分支，不凭日期推测预下载是否已开放。

预下载只写 SSMT 下载缓存，不提前替换正在运行的客户端。更新及换服需游戏关闭，
所有目标文件验证完成后再提交版本和渠道；未知 Mod、注入器及第三方文件不整体清理。
下载和解压不在 Tauri 交互线程执行。本轮开发不下载完整游戏，也不修改本机真实游戏。

## 入口与操作

- 配置路径须指向可访问的真实文件；空白、目录、失效链接及已删除文件都不可用。
  不要求手动配置的程序名称在已知游戏名称列表内。
- 没有可用的游戏进程路径时，主页主按钮显示“安装游戏”，点击先快速匹配现有客户端。
  自动匹配只检查常见安装位置与固定磁盘的浅层目录，不在启动链中递归扫描全盘。
  后端限制扫描时间、条目和深度，前端为整个入口检查提供 3.5 秒兜底；超时或找不到即
  进入安装界面，迟到结果不保存。主按钮下方“已安装? 点击此处手动指定”可以直接选取 exe。
  游戏设置中由用户主动点击的“自动匹配”仍保留完整搜索。
- 查询到本地正式版本落后时，主按钮变成“更新游戏”，点击直接开始后台更新。
  网络检查失败时保留普通启动，不伪造“必须更新”。
- 官方提供预下载分支时，主按钮左侧显示无背景的“预下载”按钮。点击直接开始，
  不弹确认、不导航、不启动游戏；显示进度与暂停操作，主启动按钮保持可用。
- 主页进入、重新获得焦点和每三分钟异步检查版本。查询不会自动发起任何下载。
- “游戏设置 → 游戏管理”提供目录、语音、更新 / 修复、预下载、恢复和原神换服。
  安装使用空的游戏目录，不使用 3DMigoto 的 `installDir`；成功后写入 `targetExePath`。
- 游戏管理先通过 `hoyoplay_status(localOnly: true)` 读取本地状态和已有版本缓存，
  随后在后台自动获取所选渠道的版本（200ms 合并快速切换）。请求带 `homeOnly: true`，
  不读取语音启动配置。选择即时生效，网络查询不禁用选项；首次加载用版本占位条和统一
  同步状态展示，失败保留本地信息与旧缓存，不伪造版本或预下载是否开放。
- 版本元数据使用独立共享 HTTP 客户端：连接上限 3 秒、单路线请求上限 8 秒，
  复用连接池和已连通路线；成功缓存 120 秒、失败冷却 10 秒，相同渠道并发请求合并。
  缓存按完整分支接口地址区分游戏和渠道，旧缓存只用于展示，实际任务仍重新验证官方分支。
  下载连接继续使用原超时；不能用页面短超时限制大文件下载。
- 点击安装、更新 / 修复、切服或预下载后，根据最终选择检查并确认执行。
  “检查版本”和“重新估算”保留为主动只读查询入口；查询结果不能回写用户已修改的选择。
  恢复操作仅走本地恢复，不依赖官方接口。
- 管理页按版本概览、客户端选项和执行区组织；版本首载占位、同步失败和实际任务错误
  分开呈现。使用真实组件及 Element Plus 的隔离浏览器夹具检查过 960px / 600px 宽度，
  覆盖自动填入版本、选择可交互及横向溢出；夹具使用模拟服务，不证明真实官方接口耗时。
  作为设置子页沿用浮窗现有卡片和按钮样式，避免重复大标题。预下载按钮只在所选渠道
  已确认有可用分支且客户端匹配时出现，未知、未开放及切换渠道期间均隐藏。
- 点击安装时查询游戏大小、预计下载量、所需可用空间和磁盘剩余空间，确认框也显示空间。
  目录、渠道、语音变化立即废弃旧估算，管理页使用 `useInstallSpace` 的手动模式。
  空间不足时不能开始安装，查询失败会显示原因并允许重试，不把未知大小当成零。
  预估只读官方 Build 统计及当前目录，不创建事务、不下载客户端；尚未创建的目录查询
  最近已有父目录所在卷。续装可利用本目录中经过官方摘要验证的缓存清单抵扣已有暂存数据。
- 原神换服只处理客户端渠道。跨国服与国际服复用经校验的分块，转换程序和数据路径，
  下载相应渠道 SDK。原客户端须先更新到目标渠道当前正式版本。
- 未声明渠道的旧配置需要在管理界面明确确认所选渠道；不根据崩铁 / 绝区零同名 exe
  自动猜测国服。语音选择会合并游戏中已安装的语音，不提供卸载语音功能。

## 文件与恢复边界

`src-tauri/src/hoyoplay/` 为独立后端模块，`src/features/gameMaintenance/` 为独立界面
与主页状态逻辑，便于后续拆成可选页面。没有修改 Native / Runtime、插件 ABI 或渲染路径。

所有大型任务在 `spawn_blocking` 中执行，最多四个文件工作线程。单次只允许一个维护任务，
同一客户端目录还有跨进程文件锁。暂停保留已验证分块与暂存文件，下次执行同一操作即可续用。
预下载在游戏运行时也可进行，不能因其存在而拒绝启动；更新、换服、恢复要求游戏关闭。

安装、更新和换服按 Sophon 块下载、校验、解压并写入暂存文件，不等待全量压缩资源下载。
单独使用的压缩块写入后释放；共享块用完释放，中途驻留上限 256 MiB，超过上限的块可能
在后续文件中重新下载。最多四个下载中的块各不超过 64 MiB。预下载刻意保留压缩块，供正式
更新时使用；不能把预下载也改成删除已完成块。暂停后的暂存文件按块重新校验、原位补齐，
不能截断重建，否则释放压缩缓存后会丧失续装进度。完整文件仍须校验及同步后才允许提交。

首次安装的空间预估是游戏与所选语音的解压统计，加 1.25 GiB 临时空间及余量，再加压缩
清单大小；其中包含 256 MiB 共享缓存、256 MiB 并发下载和 768 MiB 渠道 SDK / 小文件余量。
官方跨类别统计可能重复计数，所以采用保守上限。正式任务取得完整清单后按未完成的新文件、
现有普通暂存文件长度和实际缓存重新检查磁盘；稀疏 / 文件系统压缩文件不按逻辑长度抵扣。
不预先抵扣将来可能释放的预下载缓存或旧备份，避免安装中途空间不足。磁盘空间被其他程序
占用仍可能导致写入失败，此时保留暂存数据，重试时重新校验；不能以估算替代实际写入错误处理。

游戏目录的 `.ssmt-maintenance/` 包含：

| 内容 | 用途 |
| --- | --- |
| `owner.json` / `lock` | 确认目录归属与互斥，拒绝接管未知同名目录 |
| `cache/` | 压缩块与 `.part` 断点，按块身份和摘要区分 |
| `manifests/` / `sdk-*.zip` | 已校验的资源清单及渠道 SDK，重试时复用 |
| `stage/` | 下载中逐块写入的新文件；完成整文件校验后才能提交 |
| `backup/` / `journal.json` | 提交前的文件摘要、原文件备份及应用配置变更 |
| `completed.json` | 已提交的清理记录，避免清理中断被误当成更新失败 |

下载阶段不改原文件；提交前再次检查原文件和暂存文件摘要。文件占用导致提交失败时尝试恢复。
进程在提交时中断，下一次启动游戏会提示先到游戏管理恢复。恢复前检查全部相关文件；若玩家
之后改过文件，停止恢复并保留备份。不要自行删除 `journal.json` 或 `backup/` 绕过检查。
首次安装中断且目标路径尚未保存时，在管理界面重新选择原安装目录，再点击“恢复原客户端”。

资源路径拒绝越界、Windows 特殊名称、大小写冲突以及链接 / junction。原神根目录的
`GenshinImpact_Data` / `YuanShen_Data` 兼容别名例外：仅允许指向同一根目录下另一个
无链接的真实数据目录，名称大小写不敏感，解析后仍逐层拒绝内部链接。
文件操作沿实际目录进行并保留别名；旧清单清理按解析后的目标判断资源是否仍被使用，
事务提交和恢复拒绝多个路径指向同一文件。不能仅放行链接而继续按清单名称清理旧文件。
渠道 SDK ZIP 同样
检查路径、链接、大小和重复文件。旧文件只在官方旧清单 / SDK 证明归属且摘要未变时移除，
不递归清理未知文件。应用配置只合并本模块拥有的三个字段，保留其他设置。

## 交付验收

建议先使用独立的客户端副本，按原神、崩铁、绝区零逐项记录渠道和版本。

1. 无游戏路径且匹配不到客户端：主按钮进入安装，下面小字能选已有程序。
   配置了有效路径时保持启动行为；绝区零两种图形预设均识别。
2. 安装到空目录，选择语音，确认空间预估随目录 / 渠道 / 语音变化，不足时明确禁用安装，
   查询中其他页面可操作。安装期间观察 `.ssmt-maintenance/stage` 逐步增长，`cache` 中本次
   新下载的块不随完整下载量持续累积。下载中暂停后重新开始，确认所需新增空间减少，并且
   已落盘的块不重新下载；完成后检查 exe、`config.ini`、语音记录与目标路径，再实际启动。
3. 使用落后的客户端副本：主页显示“更新游戏”，不能误走启动。更新完成后恢复启动文案，
   实际进入游戏，检查所选及原有语音、普通 Mod 和插件组合。
4. 官方开放预下载时：按钮出现在启动左侧，点击不弹窗、不打开设置、不切换页面，
   进度可见，仍可启动当前客户端。预下载前后客户端文件摘要和版本不变。
5. 原神在同一正式版本测试国服 → B服 → 国服、国服 → 国际服 → 国服，检查 SDK 与 exe，
   SSMT 目标随之更新；未知 Mod 和自定义文件保留。账号与游戏内区服不作迁移。
6. 在测试副本中用文件占用模拟提交失败，确认恢复原版本并说明原因。需要检验进程中断恢复
   时仅对副本操作；恢复前故意修改某个目标文件，应拒绝覆盖并保留备份与记录。
7. 无网络、预下载尚未开放、磁盘不足、配置渠道不明时，应给出对应状态，不能卡住界面。

## 当前限制

使用 Sophon 分块复用和下载，尚未实现 HPatch / LDiff；更新下载量可能大于官方增量补丁。
提交采用完整新文件暂存，空间需求会高于原地打补丁，提前检查空间并保留失败现场。
预下载分块在正式更新消费时逐步清理；其他版本未使用缓存继续保留，尚无通用缓存管理页面。
本轮未完成完整客户端下载与实机游戏验收；崩坏3不在首批支持范围。

## 官方资源连接诊断

2026-10-22，绝区零本体清单曾报 `error sending request`。同一地址使用本机代理时
TLS 握手失败，直连 `HEAD` 返回 200，长度为 4,937,469 字节；不是清单地址拼错或文件缺失。
随后使用 Rust 下载完整本体清单并验证 MD5、Zstd 及 10,825 项路径与块布局通过。
原神和崩铁本体清单也分别验证了 2,744 / 11,078 项，九个渠道的元数据检查通过。

本模块 HTTP 客户端先遵循系统 / 环境代理；遇到连接、超时或临时服务器错误时，尝试另一条
直连路径，并在当前客户端内按主机记住成功路径。若已记住的直连后来失败，也可回到系统路径。
清单、渠道 SDK 和游戏分块共用这套连接逻辑，Range 与 `Accept-Encoding: identity` 在切换时
保持一致；不会每个分块都重新尝试同一故障代理。404、普通拒绝访问和重定向策略错误不会
换路反复重试。两条路径均保留官方 HTTPS 域名 / 重定向限制与正常证书校验。

错误提示展开底层 socket / TLS 原因，列出尝试的路径；URL 查询参数不进入请求错误提示，
避免输出 Build 分支密码。两个路径都失败时保留任务及缓存，玩家处理网络后重新执行即可。
只比较 HEAD 可定位连接差异，不能替代完整清单的摘要校验。对应五项本地网络故障回归及
原有维护回归共 30 项通过，涵盖代理失败回退、成功路径复用、直连失败回退、404 不重试、
错误链、查询参数隐藏、Range 保留和域名 / 重定向检查。
