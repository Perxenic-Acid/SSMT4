# Mod 标签持久化

标签定义、Mod 映射及分组映射分别保存在 Mods/.mod-tags 下的 tags.json、mod-mappings.json 和 group-mappings.json。

## 数据保留约束

扫描、搜索和标签筛选只读取映射。SQLite 索引可能过期或只覆盖部分分组，未扫描到某个路径不代表用户已删除它，不能据此清理标签。删除映射应由明确的删除操作触发，目录重命名与启停通过路径迁移保留标签。

ModTagStore 对同一游戏的公开操作串行执行，保护完整的读取—修改—写入过程。内部方法直接互调，不能再次进入队列，否则可能死锁。图标清理在队列中重新加载定义，不使用调用方的旧快照判断归属。外部 save 是显式整份替换接口；一般修改应使用 setModTags 等事务方法，不能将旧快照用于并发增量更新。

仅文件不存在时允许使用初始空值；读取错误、JSON 解析错误及结构异常必须中止操作。每份 JSON 先写 .tmp 文件再 rename 替换，避免直接截断原文件；这不提供三个文件的跨文件原子提交，也不提供多个应用实例之间的事务锁。

## 验证

运行 `node --test scripts/tests/test-mod-tags.mjs` 和 `node_modules/.bin/vue-tsc.cmd --noEmit`。
测试通过模拟 Tauri 文件 API 执行真实 Store，覆盖并发修改、路径迁移、切换标签、读取失败、格式损坏、失败后的队列恢复和临时文件写入失败。
实际 Tauri/Windows 下的文件替换和交互体验仍需应用内验证。已经被旧版覆盖删除的标签不能由此修复自动恢复，需要用户备份或历史映射。

已有备份的定位、预览和恢复见 [标签恢复流程](mod-tag-recovery.md)。
